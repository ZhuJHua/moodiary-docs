# AI policy

We welcome AI-assisted contributions. Use whatever tools help you work.

## Keep a human in the loop

AI can write the code, but you are the author and you own it. Before you ask for a review:

- **Read every line.** Don't submit output you haven't reviewed yourself.
- **Know why.** Be ready to explain in review, from your own understanding, why the change is done this way and how it fits the rest of the app.
- **Stay responsible.** If the change causes a problem after it lands, you can track it down and fix it, as you would with code you wrote by hand.

## Good practice

- Run and test the change yourself, on a device for UI changes.
- When you answer review feedback, check that each point is actually addressed. Don't rely on a tool saying so.
- Mention the tools you used in the PR's "AI usage" section, or add an `Assisted-by: <tool>` line to the description. This is optional, and it helps reviewers.
- Keep PRs focused, and leave agent working files (plans, transcripts, prompt notes) out of the diff.
- Using AI to translate or polish your English is fine.

Inspired by the AI policies of [LLVM](https://llvm.org/docs/AIToolPolicy.html), [Flutter](https://github.com/flutter/flutter/blob/main/docs/contributing/Tree-hygiene.md#ai-contribution-guidelines) and [Vite](https://github.com/vitejs/vite/blob/main/CONTRIBUTING.md#ai-policy).
